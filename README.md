# HTR T1000-E MeshCore Firmware

> ⚠️ **CUSTOM COMMUNITY FIRMWARE — NOT OFFICIAL MESHCORE FIRMWARE**
>
> This is an HTR-modified build of MeshCore for the Seeed Studio SenseCAP T1000-E. It is not affiliated with, endorsed by, or maintained by MeshCore or Seeed Studio.

## Tracker behavior

- GPS enabled by default after boot/restart
- Standard build: GPS update interval 30 seconds
- Fast build: GPS update interval 10 seconds
- Buzzer enabled by default
- BLE Companion firmware
- Normal T1000-E button controls retained
- Based on official MeshCore Companion v1.17.1

## Auto Tracker BETA

> 🧪 **BETA / WORK IN PROGRESS — EXPERIMENTAL**
>
> This build adds automatic last-known-location advertising. It is based on the tested HTR v1.17.1 tracker firmware, but the automatic advertising logic is experimental.

**[🧪 Download the HTR Auto Tracker BETA release](https://github.com/hacktherev/T1000E-MeshCore-Tracker-GPS-on/releases/tag/auto-tracker-beta)**

Behavior:

- GPS is enabled automatically.
- GPS updates at 30-second intervals.
- After boot, the firmware waits for a genuine GPS fix, then sends **one flood-routed advert** containing the live GPS position.
- After that, the firmware checks every **4 hours**.
- A new flood-routed advert is sent **only if the tracker has moved significantly** from the last advertised position.
- No advert is sent merely because the 4-hour timer expired.
- No zero-hop location adverts are generated by this feature.
- Normal telemetry behavior is unchanged.
- Buzzer remains enabled.
- Significant movement threshold in the beta is currently **100 meters**.

The goal is to keep the mesh traffic very low while maintaining a useful last-known location when live telemetry or a direct connection is unavailable.

## Why this exists

The goal is a simple tracker that can be charged, turned on, and used without first connecting a phone or remembering to re-enable GPS. GPS remains configurable through the normal MeshCore controls, but the default state is ON.

## Battery trade-off

The 30-second build is the recommended everyday tracker configuration because it reduces GNSS activity compared with more frequent fixes. The 10-second build is intended for situations where tighter location updates are worth the additional battery use.
